# 数据存储设计规格

## 目标

在“网络管理平台”下新增“数据存储”一级菜单，提供“实时数据”“历史数据”“历史归档配置”三个子菜单。页面采用前端静态 mock 数据，复用现有设备管理列表、设备详情抽屉、文件资料 Tab 和后台视觉规范。

## 页面与路由

- `web/pages/data-storage/realtime.html`：按系统切换查看设备基础信息和实时监测数据。
- `web/pages/data-storage/history.html`：按系统切换查看设备基础信息和历史监测数据，支持采集时间范围检索。
- `web/pages/data-storage/archive-config.html`：配置历史数据保留时长和定时归档任务。

`app/config/menu.js` 在“网络管理平台”之后新增“数据存储”菜单项，包含上述三个子菜单。公共侧边栏、头部、抽屉和样式继续使用现有组件。

## 交互范围

### 实时数据

- 筛选区提供系统、设备名称/编码、设备状态和查询/重置。
- 列表复用设备管理核心字段：设备名称、设备编码、所属系统、设备分类、项目/位置、运行状态、最新上报时间和操作。
- 点击行或“详情”打开设备详情抽屉，包含“基本信息”“实时数据”“文件资料”三个 Tab。
- 实时数据 Tab 使用卡片展示监测指标、当前数据、上报时间和“详情”按钮；详情按钮打开二级抽屉，展示单位、质量状态、数据来源和原始报文摘要。

### 历史数据

- 筛选区提供系统、设备名称/编码、采集开始时间、采集结束时间和查询/重置。
- 设备列表结构与实时数据一致。
- 设备详情抽屉包含“基本信息”“历史数据”“文件资料”三个 Tab。
- 历史数据 Tab 使用表格展示监测指标、数据、上报时间和操作；“详情”打开二级抽屉展示完整采集记录。
- mock 查询根据时间范围过滤记录，未填写时间时显示全部历史记录。

### 历史归档配置

- 表单字段：启用归档、历史数据保留时长、时间单位、定时任务频率、执行时间/cron 表达式和失败重试次数。
- 下方展示最近归档任务：任务名称、执行周期、最近执行时间、执行结果和下次执行时间。
- “保存配置”更新内存中的 mock 配置并提示成功；“恢复默认”回填默认值；“立即执行”模拟任务触发并更新最近执行状态。

## 数据与组件边界

- `app/data/data-storage.js` 仅提供 mock 系统、设备、实时指标、历史采样和默认归档配置。
- `app/components/data-storage.js` 负责格式化、筛选、详情抽屉、Tab 切换和页面事件绑定，通过 `data-storage-mode` 区分页面分支。
- 实时与历史页面共享设备字段和详情模板，仅替换监测数据区域；归档配置页面复用同一页面壳层和表单样式。
- 菜单只负责路由，不在 `sidebar.js` 中增加数据存储特例。

## 状态、异常与空状态

- 系统筛选、设备关键词、时间范围、当前设备和当前详情 Tab 都由页面本地状态驱动。
- 查询和重置不修改 mock 原始数据；归档保存只更新当前页面内存，刷新后恢复默认配置。
- 开始时间晚于结束时间时阻止查询并提示；保留时长为空、为 0 或非数字时阻止保存。
- 无匹配设备或历史记录时展示统一空状态；详情找不到设备时不打开抽屉且不抛出脚本错误。

## 实现与验证

- 新增三个页面、一个数据模块和一个组件脚本，最小化修改菜单配置。
- 验证菜单层级、三个 URL、系统切换、实时/历史筛选、时间校验、详情 Tab、指标/记录二级详情、归档保存/重置/立即执行。
- 在桌面和窄屏宽度检查表格横向滚动、卡片换行、抽屉宽度和空状态布局。
- 保留现有用户改动，不重置或覆盖无关文件。
