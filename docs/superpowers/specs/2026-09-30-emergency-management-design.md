# 应急管理模块设计

## 1. 目标与范围

在现有“智能监测”一级菜单下新增同级一级菜单“应急管理”，并建设六个二级菜单：

1. 应急调度台
2. 应急事件
3. 应急预案
4. 应急物资
5. 应急人员
6. 通话记录

本阶段采用“基础数据优先”的建设顺序：先完成应急人员、应急物资、应急预案、应急事件四类基础功能数据，再实现应急调度台和通话记录。所有页面使用 Mock 初始数据，并通过浏览器 `localStorage` 保存新增、编辑和状态变化，保证跨页面演示闭环。

## 2. 菜单与页面边界

```text
智能监测
  ├─ 停车记录
  ├─ 人行通行记录
  └─ 视频监控
应急管理
  ├─ 应急调度台
  ├─ 应急事件
  ├─ 应急预案
  ├─ 应急物资
  ├─ 应急人员
  └─ 通话记录
```

“应急管理”和“智能监测”是同级一级菜单。六个页面均沿用现有 B 端壳层、侧边栏、顶部上下文栏、列表页、右侧抽屉和统一反馈组件。

## 3. 方案选择

采用“数据基础优先 + 调度台聚合”方案。

- 应急人员提供统一通讯录和可调度人员池。
- 应急物资提供可调用资源和库存状态。
- 应急预案提供标准化处置流程、通知对象和资源需求。
- 应急事件承接报警中心自动转入和人工补录。
- 应急调度台只聚合和驱动上述数据，不重复维护基础信息。
- 通话记录由通讯操作自动生成，并通过 `eventId` 回溯到完整事件。

## 4. 数据关系

```text
报警中心
   │ 自动转入 / 人工补录
   ▼
应急事件 ───────► 应急预案
   │                  │
   │                  └─ 处置步骤、通知对象、资源需求
   │
   ├──────────────► 应急人员
   ├──────────────► 应急物资
   ├──────────────► 视频监控
   └──────────────► 通话记录
```

统一以 `eventId` 作为事件主键；人员、物资、预案和通话通过关联 ID 引用，不复制完整对象。

建议的本地数据键：

```text
emergency.personnel
emergency.resources
emergency.plans
emergency.events
emergency.calls
emergency.dispatch
```

## 5. 基础页面设计

### 5.1 应急人员

定位：统一通讯录与可调度人员池，覆盖管廊运维人员、各管线单位值班人员和外部应急部门。

顶部统计：在册人员、当前在线、可调度、外部单位、今日通话。

筛选字段：姓名 / 手机号 / 所属单位 / 人员类型 / 当前状态 / 是否可调度。

列表字段：姓名、所属单位、人员类型、联系方式、当前状态、所在位置、可调度状态、操作。

人员类型：管廊运维、电力值班、水务值班、燃气值班、消防/医疗/公安、应急指挥员、专业抢修人员。

核心字段：

```text
personId, 姓名, 头像/标识色, 所属单位, 部门/岗位, 人员类型,
手机号, 座机/分机, 备用联系方式, 值班时间, 当前状态,
可调度状态, 当前经纬度, 所在舱段, 专业标签, 最近更新时间
```

状态：当前状态为在线、离线、忙碌、休假；可调度状态为可调度、已调度、不可调度。

操作：新增、编辑、详情、语音呼叫、视频呼叫、短信/通知、查看当前任务、查看历史通话、设置值班状态、设置可调度状态。

详情采用右侧抽屉，分为基本信息、值班信息、当前位置、关联事件、通话记录。

### 5.2 应急物资

定位：为事件预案和调度台提供可调用资源。

顶部统计：物资总数、可用物资、低库存、已占用、临期物资。

筛选字段：物资名称 / 分类 / 所在仓库 / 状态 / 是否低库存。

列表字段：物资名称、分类、规格、可用数量、所在位置、负责人、状态、操作。

物资分类：消防器材、防护装备、抢修工具、排水设备、通风设备、临时照明、通讯设备、医疗急救、交通疏散。

核心字段：

```text
resourceId, 物资名称, 物资分类, 规格型号, 计量单位,
总库存, 可用数量, 已占用数量, 安全库存, 所在仓库/舱段,
具体位置, 负责人, 有效期, 状态, 最近盘点时间
```

状态：可用、已占用、维修中、报废。

操作：新增、编辑、入库、出库、调拨、锁定、释放、使用记录、地图定位。预案配置资源需求，调度台执行预案时只展示并锁定可用资源。

### 5.3 应急预案

定位：将处置经验固化为标准化操作流程。

顶部统计：预案总数、已发布、草稿、最近更新、覆盖事件类型。

筛选字段：预案名称 / 事件类型 / 风险等级 / 适用区域 / 状态。

列表字段：预案名称、事件类型、响应等级、适用区域、步骤数、版本、状态、操作。

核心字段：

```text
planId, 预案名称, 预案编码, 事件类型, 响应等级, 适用区域,
触发条件, 预案版本, 状态, 编制人, 审核人, 发布时间, 更新时间
```

步骤字段：

```text
stepId, 步骤序号, 步骤名称, 步骤类型, 执行角色, 是否必须完成,
超时时间, 前置步骤, 通知对象, 人员类型, 关联物资,
关联视频区域, 完成条件
```

步骤类型：信息确认、人员通知、人员调度、物资调拨、视频联动、广播通知、区域隔离、现场反馈、事件升级、事件关闭。

预案详情采用大抽屉和步骤时间线，支持草稿、发布、停用和版本查看。

### 5.4 应急事件

定位：承接报警中心事件和人工上报事件，是全部调度业务的主线。

顶部统计：待确认、处理中、待关闭、已关闭、P1 高等级事件。

筛选字段：事件编号 / 事件类型 / 等级 / 来源 / 状态 / 时间范围 / 所属区域。

列表字段：事件编号、事件类型、等级、发生位置、来源、当前状态、负责人、更新时间、操作。

核心字段：

```text
eventId, 事件编号, 事件标题, 事件类型, 事件等级,
事件来源, 报警设备/报警规则, 发生时间, 发现时间,
发生位置, 所属项目/区段/舱室, 事件描述, 图片/附件,
匹配预案, 当前状态, 当前负责人, 已调度人员数,
已占用物资数, 关联视频数, 最近更新时间, 关闭时间
```

事件来源支持报警中心自动转入和人工补录。

状态机：

```text
待确认 -> 已确认 -> 处理中 -> 待复核 -> 已关闭
待确认 -> 误报关闭
处理中 -> 已升级
处理中 -> 处置失败
```

操作：确认、匹配/切换预案、进入调度台、指派负责人、调度人员、调用物资、查看附近视频、查看处置时间线、关闭、导出。

事件详情大抽屉包含事件概况、预案执行进度、人员调度、物资调用、视频联动、通话记录、操作时间线。

## 6. 应急调度台设计

采用已确认的 B 方案：地图全屏 + 底部事件流。地图是主工作区，底部工作台是处置操作区。

页面区域：

```text
顶部指挥栏：事件选择、事件等级、实时连接、图层、全屏
地图主区域：人员、车辆、物资、摄像机、事件点、区段和路线
地图工具：缩放、定位、图层、圈选呼叫、测距、路线规划、复位
底部工作台：事件队列、预案执行、调度对象、视频联动、操作时间线
```

默认图层：管廊区段、舱室边界、当前事件、在线人员、应急车辆、应急物资、视频点位、已调度对象、影响范围、行进路线和疏散路线。

颜色约定：红色代表事件和高等级风险，蓝色代表人员/车辆，绿色代表可用物资，紫色代表视频，黄色代表影响范围或预警。

### 6.1 天地图离线适配

地图业务层不直接绑定地图实现，统一通过配置和适配器加载离线瓦片：

```js
window.EMERGENCY_MAP_CONFIG = {
  provider: "tianditu-offline",
  tileRoot: "./assets/maps/tianditu",
  baseLayer: "vec",
  annotationLayer: "cva",
  projection: "EPSG:3857",
  defaultCenter: [longitude, latitude],
  defaultZoom: 15
};
```

瓦片目录约定：

```text
assets/maps/tianditu/
├─ vec/{z}/{x}/{y}.png
├─ cva/{z}/{x}/{y}.png
├─ ter/{z}/{x}/{y}.png
└─ cia/{z}/{x}/{y}.png
```

首期支持矢量底图、注记、管廊线路、业务点位、影响范围、平移缩放、点位点击、圈选和高亮。离线瓦片未放入项目时，使用示意底板保持同一业务接口。

### 6.2 圈选呼叫

```text
点击圈选呼叫
  -> 绘制圆形或多边形
  -> 计算范围内人员、车辆和资源
  -> 底部显示选中对象
  -> 选择人员/车辆/全部
  -> 选择通信方式
  -> 批量呼叫
  -> 自动生成通话记录
```

圈选结果显示人员总数、在线人数、可调度人数、车辆数和附近物资点数。批量操作前展示确认列表，支持语音、视频、短信和应急广播。

### 6.3 预案执行

事件确认后按事件类型、事件等级和区域自动推荐预案；指挥员确认后进入步骤执行。

默认步骤示例：确认事件、信息通报、人员调度、物资调拨、视频联动、现场反馈、事件关闭。

步骤状态：未开始、执行中、已完成、已跳过、执行失败。当前步骤完成后才能进入下一步；跳过必须填写原因；失败提供重试。

### 6.4 视频联动

根据事件点计算附近摄像机，按距离和在线状态排序，默认打开最近四路视频。调度台只提供快速预览和跳转视频监控，不复制视频监控页面的完整控制能力。

## 7. 通话记录设计

通话记录是独立页面，也是所有调度操作自动生成的结果。

顶部统计：今日通话、接通率、平均时长、未接通、事件关联通话。

筛选字段：事件编号 / 通话类型 / 主叫人 / 被叫人 / 所属单位 / 通话结果 / 时间范围。

列表字段：通话时间、事件编号、主叫人、被叫人、通话类型、通话结果、时长、操作。

核心字段：

```text
callId, eventId, 事件编号, 主叫人, 被叫人, 主叫单位, 被叫单位,
通话类型, 发起来源, 发起时间, 接通时间, 结束时间, 通话时长,
通话结果, 录音地址/状态, 关联预案步骤, 操作人
```

通话类型支持单呼、群呼、视频呼叫、短信和广播；来源支持调度台、事件详情和人员通讯录。

通话结果支持已接通、未接通、拒接、超时、失败。详情抽屉展示双方、事件、时间线、结果、录音播放 Mock、预案步骤和审计信息。

以下操作自动生成记录：人员页面单独呼叫、调度台圈选呼叫、预案通知步骤、事件详情通知、视频呼叫、短信和广播。

## 8. 事件处置闭环

```text
报警中心自动转入
  -> 应急事件待确认
  -> 匹配应急预案
  -> 调度台定位事件
  -> 打开附近视频
  -> 圈选人员和车辆
  -> 批量呼叫/调度
  -> 锁定应急物资
  -> 执行预案步骤
  -> 形成通话与操作记录
  -> 事件关闭
```

首期演示场景使用“东段 K2+340 燃气泄漏 P1 事件”，贯穿报警转入、预案匹配、地图定位、视频联动、人员呼叫、物资锁定、步骤完成和通话记录查询。

## 9. 交互与验收边界

- 新增、编辑、删除/停用、状态变更均写入 `localStorage`。
- 页面切换和刷新后 Mock 数据仍可见。
- 事件、人员、物资、预案、通话可通过 ID 互相跳转。
- 调度台的圈选、呼叫、锁定、预案步骤、视频联动均有可见反馈。
- 所有调度操作都能在事件时间线和通话记录中追溯。
- 离线地图缺失时不阻塞页面加载，使用示意底板作为降级状态。
- 右侧抽屉用于详情和编辑；地图工作区不因查看详情而离开当前事件上下文。
- 真实接口、实时定位、真实通话、真实录像播放和后端权限不在本阶段实现范围内。
