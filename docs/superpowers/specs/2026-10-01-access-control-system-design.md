# 门禁系统人员通行记录设计

## 目标

在“视频监控”一级菜单下方增加“门禁系统”一级菜单，并在页面中以只读列表呈现从第三方门禁系统获取的人员通行记录。

## 范围

- 新增一个一级导航项“门禁系统”，使用门禁相关图标，直接进入通行记录页面。
- 页面不提供人员、设备或通行记录的新增、编辑、删除、远程开门等控制能力。
- 列表数据使用现有原型的本地 mock 数据模拟第三方返回结果，字段与截图和已有“人行通行记录”页面保持一致。
- 保留平台统一的筛选、重置、导出反馈和记录详情查看交互，不改变其他菜单或业务页面。

## 页面结构

页面沿用 `tob-ui.css` 和 `monitoring.css` 的后台布局：

1. 顶部筛选区：通行时间、通行结果，以及“重置”“搜索”按钮。
2. 列表区：标题“门禁系统”，右侧显示导出按钮；表格字段为序号、姓名、通行方式、门禁设备、通行位置、通行时间、通行方向、通行结果、操作。
3. 操作列只提供“查看”，用于打开抽屉查看该条记录的通行照片、结果和时间。
4. 表格底部显示当前筛选结果条数和页码占位，沿用现有原型分页样式。

## 数据与状态

- 页面数据字段：`name`、`method`、`device`、`location`、`time`、`direction`、`result`。
- `result` 仅允许“成功”和“失败”两种展示值，分别使用现有绿色/红色语义色，并不以颜色作为唯一信息。
- 搜索按日期前缀和通行结果过滤；重置恢复完整第三方 mock 列表。
- 导出按钮仅给出“已按当前筛选条件生成文件（Mock）”的抽屉反馈，不下载或写入真实文件。
- 查看抽屉显示一张现有门禁现场图片；图片加载失败时仍保留记录元数据。

## 菜单与路由

- 在 `app/config/menu.js` 中，将 `access-control` 一级项插入 `video-monitoring` 后方。
- 菜单项直接指向 `../monitoring/access-control.html`，页面 `data-menu-key="access-control"`、`data-page-section="门禁系统"`、`data-page-title="门禁系统"`。
- 原隐藏的 `smart-monitoring.pedestrian` 菜单项不再作为对外入口，保留文件以避免影响既有原型和历史链接。

## 验证标准

- 打开任一带公共侧栏的页面时，可在“视频监控”下方看到“门禁系统”，点击后能进入新页面且当前菜单高亮。
- 新页面能渲染截图所需的九列表头和至少八条 mock 记录。
- 日期、结果筛选和重置会正确更新列表条数；导出和查看操作有可见反馈。
- 页面在窄屏下沿用横向表格滚动，不造成主页面布局溢出。
