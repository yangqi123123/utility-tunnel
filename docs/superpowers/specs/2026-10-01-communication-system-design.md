# 通信系统功能设计

## 目标

在“视频监控”一级菜单下新增“通信系统”一级菜单，提供第三方通信平台数据的统一呈现入口。平台不承担通信控制和原始数据采集，仅完成呼叫信息列表展示、呼叫位置关联以及通话记录入库后的查询。

## 页面与导航

- 新增一级菜单 `communication-system`，位置紧跟在 `video-monitoring` 后方。
- 菜单默认跳转 `web/pages/communication/communication.html`，页面标题为“通信系统”。
- 页面使用现有侧边栏、顶部导航、标签页、卡片、表格和抽屉组件，不改变既有视频监控路由。

## 页面布局

页面为单页通信工作台，按值守流程从上到下组织：

1. **状态与统计区**：显示第三方接口连接状态、最近同步时间，以及呼叫总数、待处理、通话中、今日已完成四项摘要。
2. **呼叫信息区**：左侧为呼叫信息列表，支持关键字、呼叫状态、时间范围筛选；列表展示呼叫编号、终端名称、呼叫类型、位置、开始时间、持续时长和状态。选中记录后，右侧位置面板同步更新。
3. **位置关联区**：使用管廊示意图风格的静态定位画布，显示选中终端所在管廊、舱室、区段和坐标标记；提供“查看位置详情”操作打开抽屉。
4. **通话记录区**：按当前筛选条件展示已入库通话记录，支持按终端、通话类型、日期查询，以及导出按钮。点击记录打开详情抽屉。

## 数据模型

模拟数据与未来第三方字段保持一一映射，数据层集中在页面脚本中，后续可替换为接口适配器：

- `calls`: `id`、`terminal`、`type`、`location`、`startedAt`、`duration`、`status`、`priority`、`position`。
- `records`: `id`、`callId`、`terminal`、`type`、`location`、`startedAt`、`endedAt`、`duration`、`result`、`operator`。
- `integration`: `status`、`lastSyncAt`、`source`、`latency`。

第三方接口异常时只影响状态提示和刷新反馈，不阻塞已入库数据查询；页面通过状态徽标明确“已连接/同步中/异常”。

## 交互与状态

- 点击呼叫行：更新选中态、定位画布和通话记录筛选；再次点击同一行保持选中。
- 点击“刷新数据”：更新同步时间和列表状态，并提示“已完成同步”；原型使用本地模拟刷新，不发起外部请求。
- 点击位置详情或通话记录：使用现有抽屉组件展示完整字段。
- 查询无结果时显示统一空状态；筛选、分页和导出按钮保持可用。
- 响应式断点沿用现有监控页面规则：桌面端为左右分栏，窄屏下位置面板移动到列表下方，表格支持横向滚动。

## 验证范围

- 菜单渲染与 active 状态：通信系统位于视频监控之后，页面打开后高亮正确。
- 页面行为：筛选、选中呼叫、位置同步、记录查询、详情抽屉、刷新提示均可操作。
- 回归检查：现有视频监控页面和侧边栏脚本无语法错误，通信页面可通过本地静态服务器访问。
