# 电力监测系统设计规格

## 目标

在现有管廊监控后台中新增“电力监测系统”一级菜单，并提供一个以运行总览为入口的电力运营监测工作台。平台只负责展示和分析第三方电力数据，不在本地模拟采集链路或替代第三方控制系统。

## 导航与页面边界

- 一级菜单放置在“视频监控”之后，使用电力/闪电语义图标。
- 菜单包含三个页面入口：运行总览、设备监控、事件记录。
- 首期实现运行总览页面；另外两个入口先保持为可扩展的导航项，不新增空壳页面。
- 页面沿用现有后台壳层：侧边栏、顶部面包屑与路由页签、`tob-ui.css` 设计令牌。

## 运行总览布局

1. 页面标题区：显示“电力系统运行总览”、第三方数据接入状态和最近更新时间。
2. 指标区：供电健康度、当前总负荷、运行设备数、未处理告警数四个指标卡。
3. 主工作区：左侧为一次系统图，展示高压进线、变压器、低压母线/出线、UPS/应急负荷的链路状态与关键数值；右侧为关键设备清单，覆盖变压器、UPS、柴油发电机和 ATS。
4. 追溯区：并列展示实时告警和运行事件记录，提供查看全部入口与事件类型/状态标签。

## 数据与状态

- 组件使用本地 mock 数据承载页面行为，字段按第三方数据语义命名，后续可替换为接口适配层。
- 设备状态统一映射为正常、关注、告警、待机、已恢复等语义状态，并使用绿色、黄色、红色、蓝色区分。
- 未连接或数据过期时应显示接入状态异常，不阻塞页面布局；本期以静态已接入状态展示。
- 页面不提供远程控制、参数写入或告警确认操作，避免越过第三方系统边界。

## 视觉与响应式

- 遵循 TOB 规范：浅灰蓝页面背景、白色低圆角面板、8px 间距节奏、中高信息密度。
- 一次系统图使用 CSS 结构化节点与连线表达，不依赖新增图片资源，保证可读性和可维护性。
- 视口变窄时：指标卡降为两列再单列；主工作区和追溯区改为单列；一次系统图允许连线隐藏但节点顺序保持。
- 所有按钮、入口和状态标签保持现有字体、边框与交互样式。

## 验证

- 验证菜单出现在视频监控之后，运行总览页面能正常打开且当前菜单高亮。
- 验证一次系统图、关键设备、告警和事件内容在桌面宽度下无重叠或截断。
- 在窄视口检查布局是否单列、文本是否溢出。
- 运行现有相关测试，并使用浏览器检查页面实际渲染。
