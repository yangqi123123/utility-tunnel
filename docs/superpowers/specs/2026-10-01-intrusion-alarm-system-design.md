# 入侵报警系统设计

## 背景与目标

在“视频监控”一级菜单下新增“入侵报警系统”一级菜单。平台不负责采集或控制入侵报警设备，数据由第三方系统提供；本次原型只验证第三方入侵信号在平台内的列表接收、入侵位置展示和设备状态呈现。

## 信息架构

- 在 `app/config/menu.js` 中新增顶级菜单项 `intrusion-alarm`，位置紧跟 `video-monitoring`。
- 菜单直接进入 `web/pages/monitoring/intrusion-alarm.html`，不增加二级菜单。
- 页面复用现有 `app-shell`、公共侧栏、顶部栏、`tob-ui.css` 和右侧抽屉机制。

## 页面布局

页面采用列表主工作区加右侧详情的双栏布局，保持中高密度的后台操作风格。

1. 页面头部显示“入侵报警系统”、第三方数据源标识、最近同步时间和“刷新”操作。
2. 统计区显示当前报警数、一级报警数、在线主机数、离线/故障主机数。
3. 筛选区包含报警事件、报警主机 ID、报警类型、报警级别、报警时间和处理状态；提供重置、搜索按钮。
4. 报警列表保留用户示例中的核心字段：报警事件、报警主机 ID、报警类型、报警级别、报警时间；补充入侵位置、设备状态、处理状态和详情操作。
5. 右侧详情区展示选中事件的定位路径（管廊、舱室、区段、防区）、报警信号时间线、主机/防区状态和第三方来源。定位使用轻量的管廊示意图与定位点，不引入新的地图服务依赖。

## 数据模型与数据流

页面先以内置 mock 数据模拟第三方返回结构，后续对接时只替换数据适配层，不改动渲染和交互层。单条事件至少包含：

```js
{
  id, event, hostId, type, level, time,
  status, location: { corridor, cabin, section, zone },
  device: { name, status, lastSeen, signalStrength },
  source, timeline
}
```

- `event`、`hostId`、`type`、`level`、`time` 对应第三方列表字段。
- `location` 用于定位展示；缺少定位数据时显示“待定位”，不得伪造坐标。
- `device.status` 使用在线、离线、故障三态；颜色与文字同时表达，避免只依赖颜色。
- `source` 固定显示第三方系统名称和同步状态；页面不提供新增、编辑、删除或控制设备的入口。
- 刷新操作只重跑 mock 适配器并更新时间戳；异常时保留上次列表并显示同步异常提示。

## 交互与状态

- 默认选中最新一条一级报警，右侧详情同步展示。
- 点击列表行切换选中事件；点击“详情”打开公共右侧抽屉，抽屉内展示完整信号详情与时间线。
- 筛选、重置、分页（若数据量超过当前页容量）均在前端完成，保持与现有原型的交互方式一致。
- 空结果显示筛选无结果状态；没有任何第三方数据时显示数据为空状态；同步失败显示错误提示和重试按钮。
- 不提供处理闭环和第三方设备控制，避免暗示平台拥有写入权限。

## 视觉与响应式约束

- 复用 TOB 设计 token：浅灰蓝页面背景、白色面板、低圆角、蓝色选中态，8px 间距节奏。
- 表格保持可横向滚动，关键列不被压缩；右侧详情在窄屏下移动到列表下方。
- 状态标签使用红色表示一级/故障，黄色表示二级/待确认，蓝色表示三级，绿色表示在线/正常。
- 定位示意图是信息表达组件，不作为装饰性大图；不增加渐变大背景、营销式 hero 或嵌套卡片。
